--------------------------------
KEY OBSERVATIONS
--------------------------------

1. At 10M records, full table scans became extremely expensive,
   requiring 35–50 seconds per query.

2. The system showed real distributed-system stress, including
   scanner lease expiration and query instability.

3. Query execution became I/O-bound, with multiple gigabytes
   of data scanned per query.

4. Secondary indexing reduced query latency to sub-second levels,
   demonstrating dramatic performance gains (~75x–160x).

5. Index creation cost increased significantly, requiring
   approximately 160+ seconds per index.

6. At this scale, indexing is no longer an optimization but
   a necessity for practical query performance.

--------------------------------
CONCLUSION
--------------------------------

At 10M records, Apache Phoenix demonstrated both scalability
and system limitations. While full-table scans became impractical
due to high latency and system stress, secondary indexing enabled
efficient query execution with sub-second response times.

The experiment highlights the importance of index design in large-scale
NoSQL systems and demonstrates real-world distributed system behavior,
including failure modes under heavy load.

This stress test validates Phoenix as a powerful SQL layer over HBase,
while also exposing tradeoffs in write cost, system stability, and
large-scale query execution.
