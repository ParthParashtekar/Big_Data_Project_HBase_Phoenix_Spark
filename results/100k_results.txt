--------------------------------
KEY OBSERVATIONS
--------------------------------

1. Secondary indexing significantly reduces query execution time
   for selective filters.

2. Query execution plans transition from FULL SCAN to RANGE SCAN,
   indicating efficient index utilization.

3. Index creation introduces overhead (~5.7 seconds per index),
   but this cost is amortized over repeated query execution.

4. Performance improvement becomes more pronounced as dataset size increases.

--------------------------------
CONCLUSION
--------------------------------

At 100k records, Apache Phoenix indexing provides substantial
performance gains (6–8x) by avoiding full table scans and enabling
direct index-based access. The tradeoff between index creation time
and query efficiency is justified for analytical workloads with
frequent query execution.
